# i1 review and bounded experiment

Request: review `notes/idea/i1.md` and try any method not already explored.
Reference is the verified runtime variant `submissions/runtime_049_252862932.py`:
stable320 total 252,862,932, average 790,196.6625, five-second contest limit.
All existing checkpoints and the frozen benchmark are retained.

The main backward-target identity, exact operation replacement, neutral ties,
identity slots, complete-state beam search, and inventory upper bound already
exist in earlier experiments and the retained solver. The distinction worth
testing is full-state **beam reconstruction of an internal block against the
exact backward labels of its unchanged suffix**. Existing `regret_fragment.py`
uses a single greedy trajectory through each such gap; its greedy and two-step
variants were rejected on measured comparisons.

Hypothesis: several competing trajectories through a longer block can discover
coordinated changes that earlier coordinate, pair/triple, and greedy-gap repairs
miss. The candidate keeps the reference sequence unless exact final matches
increase. Try lengths 4/8/16/32, a narrow beam, deterministic expansion limits,
and full grid-plus-stamp state deduplication. Both scored stamp labels and
unscored grid labels must be handled. Include depth zero and shorter repairs.

Validation: independent canonical transitions and rotation involutions, an
exhaustive two-step oracle, randomized fixed-suffix score equalities, parent
floor/budget/determinism checks, then frozen smoke and development benchmarks.
Only a promising candidate proceeds to stable320, readiness and runtime checks;
only a strict measured stable improvement can create a checkpoint.

## Implemented probe

`solvers/experiments/i1_block_fragment.py` implements complete packed states,
full legal-action expansion, exact scored-label masks on both board and stamp,
whole-state deduplication, and a retained incumbent trajectory within the beam.
The outer repair independently replays a candidate before accepting any strict
final-score gain. It also cancels consecutive identical operations exactly.
The budget is deterministic and counts all generated transitions, including
incumbent transitions; a final exhausted layer can be truncated by that cap.

The initial candidate is `solvers/experiments/i1_block_beam.py` (98,653 bytes),
generated by `python tools/build_i1_candidate.py`. Defaults requested by the
builder: 8 rounds, beam width 8, total 160,000 generated transitions. The helper
adapts rounds and lengths to afford useful layers; this does not promise that
all of lengths 4/8/16/32 are explored on every instance. In particular, N30/D2
gets one suffix trial. A second candidate uses `--internal-first`, producing
`solvers/experiments/i1_block_internal.py` (98,647 bytes) to prioritize an
internal block when only one trial fits.

## Interpretation

All six measured gains came from rebuilding **suffixes**, at depths 4, 5, or 8;
the N9/K5 case rebuilt its entire five-operation sequence. The replay also
observed nine internal-block trials on these winning inputs, but none improved
their incumbent. Thus the result supports retained block-beam reconstruction,
especially suffix replacement. It does **not** demonstrate an extra benchmark
benefit specifically from live backward labels inside internal blocks. Those
labels are verified by canonical and exhaustive tests; wider/deeper internal
search remains a possible future experiment. Long requested block sizes adapt
down to the fixed budget, so this was not a universal length32/width64 search.
