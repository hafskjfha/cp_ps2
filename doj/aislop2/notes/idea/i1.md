I would use **beam search over the complete grid-and-stamp state**, followed by **local search on the operation sequence**.

The most useful trick is that, for a fixed operation sequence, you can propagate the target backward through the swaps. This lets you evaluate how replacing one operation changes the **final** score in \(O(D^2)\), including all effects on future stamp contents.

## 1. Start with beam search, not just greedy stamping

Let \(m=D^2\). For an operation \(o=(x,y,r)\), let \(g_o(u,v)\) be the grid cell that contacts reference stamp cell \((u,v)\).

Its immediate change in the number of matching grid cells is

\[
\Delta(o)=
\sum_{u,v}
\left(
[S_{u,v}=T_{g_o(u,v)}]
-
[A_{g_o(u,v)}=T_{g_o(u,v)}]
\right).
\]

Thus, all possible operations can be evaluated in

\[
O\!\left(4(N-D+1)^2D^2\right)
\]

per state.

A greedy solver repeatedly chooses the largest \(\Delta(o)\). This is a useful baseline, but it ignores the quality of the colors picked up by the stamp. Two moves with the same immediate gain can have very different continuations.

### Beam state

Each state should contain the complete grid, the stamp **in reference orientation**, its current match count, and information for reconstructing the operation sequence.

At each depth, expand the beam using every legal operation and retain the best \(B\) resulting states, ranked initially by their current match count. Randomize equal-score ties.

**Keep the best solution encountered at any depth, including depth zero.** Do not stop merely because the next move has a negative immediate gain: it may prepare a useful stamp.

An initial beam width of roughly \(16\)–\(64\) is a reasonable parameter to test in C++, with the actual width governed by a timer.

### Important implementation details

Do not copy the entire grid for every candidate child. First evaluate candidates and store only small records such as

```text
(resulting score, parent index, operation)
```

Then construct full states only for the selected children.

Deduplicate states using a hash that includes **both the grid and the stamp**. Identical grids with different stamp contents are not equivalent states.

Also, consecutive identical operations can be forbidden. Applying the same \((x,y,r)\) twice restores the entire previous state, so those two operations can always be removed.

## 2. The key trick: propagate target colors backward

Beam search produces a good initial sequence. Now consider optimizing that sequence directly.

Flatten the board and stamp into one array containing

\[
V=N^2+D^2
\]

positions. An operation is just \(D^2\) disjoint swaps between stamp positions and grid positions.

Define a final label array \(B_L\):

\[
B_L[p]=
\begin{cases}
T_p, & p \text{ is a grid position},\\
\bot, & p \text{ is a stamp position}.
\end{cases}
\]

Here \(\bot\) means “this position does not contribute to the score.” In implementation, use the value \(C\), which is different from every actual color.

For a sequence \(o_0,o_1,\ldots,o_{L-1}\), construct arrays backward:

\[
B_t=\operatorname{swap}_{o_t}(B_{t+1}).
\]

In other words, copy \(B_{t+1}\), then apply operation \(o_t\) to the labels just as though they were colors.

### Meaning of these labels

\(B_t[p]\) is the desired color of the item currently at position \(p\), considering where that item will end up after operations \(t,\ldots,L-1\).

If \(X\) is the complete state immediately before operation \(t\), then executing the fixed suffix gives final score

\[
M=\sum_p [X[p]=B_t[p]].
\]

Comparisons against \(\bot\) are always false.

Notice that a stamp position can now have a real target-color label: its color may be deposited on the grid later. Conversely, a grid position can have label \(\bot\): its color may finish on the stamp.

This provides an **exact future value for stamp contents**, rather than an approximate stamp-quality bonus.

**When propagating backward, use the same operation and the same \(r\), not the inverse rotation.** Each operation, expressed in reference stamp coordinates, is an involution: applying those same disjoint swaps twice restores the state.

## 3. Evaluate an operation replacement in \(O(D^2)\)

Suppose we want to replace operation \(o_t\).

Let \(F_t\) be the complete color state immediately before it, and let

\[
B=B_{t+1}
\]

represent the unchanged suffix after it.

For a candidate operation \(o\), consider one of its swap pairs: stamp position \(s\) and grid position \(g\). The change in final score caused by swapping this pair, relative to leaving it unchanged, is

\[
\begin{aligned}
d(s,g)={}&[F_t[s]=B[g]]
+[F_t[g]=B[s]]\\
&-[F_t[s]=B[s]]
-[F_t[g]=B[g]].
\end{aligned}
\]

Sum over the stamp:

\[
G_t(o)=\sum_{(s,g)\in o}d(s,g).
\]

Then replacing the old operation with a new one changes the final score by exactly

\[
\boxed{
\Delta M=
G_t(o_{\mathrm{new}})
-
G_t(o_{\mathrm{old}})
}.
\]

No suffix simulation is necessary.

This evaluates all delayed consequences correctly. An operation that loses grid matches immediately can still have positive final value because it picks up colors used profitably later.

### Add an internal no-op

Include an internal identity operation with

\[
G_t(\mathrm{id})=0.
\]

Pad a shorter solution to \(K\) slots with these identities. They allow local search to remove unhelpful operations or fill unused slots.

Identity operations are only an internal representation; omit them from the output.

## 4. An inexpensive exact coordinate-improvement sweep

Build all backward label arrays, then walk through the sequence from left to right.

At each position, evaluate every legal replacement and the identity operation, choose the best one, and apply it to the running prefix state.

```text
improve(sequence):
    B[K] = target labels on grid, ⊥ on stamp

    for t = K-1 down to 0:
        B[t] = copy(B[t+1])
        apply sequence[t] to B[t]

    F = original grid-and-stamp state

    for t = 0 to K-1:
        old_gain = gain(F, B[t+1], sequence[t])

        chosen = operation maximizing gain(F, B[t+1], operation)
                 among all legal operations and identity

        new_gain = gain(F, B[t+1], chosen)

        final_score += new_gain - old_gain
        sequence[t] = chosen
        apply chosen to F
```

The backward arrays remain valid during this sweep: at position \(t\), only earlier operations have been changed, while \(B_{t+1}\) depends exclusively on later operations.

Since the old operation is always one of the candidates, **every replacement is non-worsening for the actual final score**. Randomizing ties lets the search move across equal-score solutions.

### Complexity

Let

\[
Q=4(N-D+1)^2
\]

be the number of legal operations. A sweep costs

\[
O(KQD^2+KV)
\]

and uses \(O(KV)\) memory.

For \(N=30,D=3,K=180\), the operation evaluations contain

\[
180\cdot 3136\cdot 9
=
5{,}080{,}320
\]

swap-pair terms per sweep. This is small enough to make repeated sweeps worth considering.

A useful optimization is to precompute, for the current slot,

\[
H[s][g]
=
[F_t[s]=B[g]]
+[F_t[g]=B[s]]
-[F_t[s]=B[s]]
-[F_t[g]=B[g]]
\]

for every stamp position \(s\) and grid position \(g\). Each candidate then needs just \(D^2\) table lookups and additions.

## 5. Escape local optima by rebuilding blocks

Single-operation improvement is cheap, but it can get stuck: changing a pickup move may require changing the subsequent placement move as well.

The same backward-label idea supports **block replacement**.

Choose an interval of operation slots

\[
[l,r).
\]

Keep the prefix before \(l\) and suffix starting at \(r\) fixed. Compute the state \(F_l\) after the prefix and the backward labels \(B_r\) for the suffix.

Now search for a new sequence of at most \(r-l\) operations, starting from \(F_l\), with objective

\[
J(X)=\sum_p[X[p]=B_r[p]].
\]

This objective is exactly the final grid match count after the unchanged suffix is executed.

Therefore, the beam-search code can be reused for this subproblem. The only difference is that its target labels may now appear on the stamp as well as the grid, so operation gains use the four-comparison formula above.

Try a mixture of block lengths, such as \(4,8,16,32\), with narrower beams, perhaps \(8\)–\(16\). Occasionally rebuild a suffix instead of an internal block.

Accept the replacement only when it improves the score, or ties it with a different state trajectory. Keep the original block as the fallback: a limited beam is not guaranteed to rediscover it.

This is much more purposeful than changing several operations randomly. It explicitly searches for coordinated pickup-and-placement changes while accounting for everything that happens afterward.

## 6. A practical five-second strategy

I would implement the following overall search:

```text
best = empty sequence

run randomized greedy once
update best using its best prefix

run one or more randomized beam searches
update best using every promising prefix

while sufficient time remains:
    choose a strong saved sequence

    perform an exact coordinate-improvement sweep
    try several beam-based block or suffix replacements

    update best

simulate best once more
keep its best prefix
output it, omitting internal identities
```

I would spend most of the initial budget on beam search and use the remaining budget for sequence repair. The relative allocation needs testing; I would not assume that many coordinate sweeps are better than another beam run.

Use a hard deadline with a safety margin, and always retain a complete valid best-so-far answer. All candidate actions should use precomputed lists of their \(D^2\) grid indices, including rotation.

### Small experimental check

I tested basic implementations on uniformly random synthetic instances. These are individual sanity checks, not the problem’s evaluation set:

| \(N\) | \(D\) | \(C\) | \(K\) | Greedy matches | Beam matches, width \(32\) |
|---:|---:|---:|---:|---:|---:|
| 30 | 3 | 6 | 180 | 645 | 692 |
| 30 | 2 | 6 | 180 | 662 | 710 |
| 20 | 3 | 4 | 180 | 326 | 360 |

On the third instance, subsequent block repair and coordinate polishing reached \(365\) matches. On the first two, that particular repair run did not improve the beam result. This suggests making **beam search the main search mechanism**, with backward-target optimization as a cheap, exact refinement tool rather than relying on single-operation local search alone.

### A useful stopping bound

Let \(a_c,s_c,t_c\) be the counts of color \(c\) in the original grid, original stamp, and target. Since swapping preserves total color counts,

\[
M\le
U=\sum_{c=0}^{C-1}\min(t_c,a_c+s_c).
\]

Reaching \(U\) proves that no higher match count is possible, so the search can stop. The bound need not be attainable because of operation restrictions.

Throughout the implementation, color \(0\) is an ordinary color. Only the separate sentinel \(\bot=C\) means “unscored.”

**The central idea is to search over complete sequences, while transporting target labels backward to make future stamp effects exactly and cheaply evaluable.**
